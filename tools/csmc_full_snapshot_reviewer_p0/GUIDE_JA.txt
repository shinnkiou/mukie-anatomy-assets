CSMC FULL SNAPSHOT REVIEWER P0 日本語ガイド
===========================================

目的
----
巨大なFull Snapshot ZIPをChatGPTへ毎回渡さず、
Windows側で解析ソフトを動かし、
小さいレポートだけをChatGPTへ返すための司令塔です。

今回の対象:
  C:\Users\nurun\CSMC_ANALYSIS\PRIVATE_FULL_SNAPSHOT\CSMC_FULL_SNAPSHOT_20260914_214659.zip
  C:\Users\nurun\CSMC_ANALYSIS\PRIVATE_FULL_SNAPSHOT\CSMC_FULL_SNAPSHOT_FOCUSED_20260914_232435.zip

今回の主目的:
  character BLOBを最初に解釈し、
  MODELER内部objectへ変換するconsumer候補を
  2つのFull Snapshotから特定すること。

二次目的:
  そのconsumer側の経路と
  posed VBO upload側の内部関数を接続できる候補を探すこと。

再調査しない:
  SQLite外層の再発見
  CLIP_STUDIO_3D_DATA2ヘッダの再発見
  一般的なModelData文字列探索
  VBO 1,160,128 bytes / stride 32 / 36,254 verticesの再確認
  UV固定の再確認
  0x140f62d20周辺の無目的な反復探索
  一般strings総当たり
  広域XREF総当たり

================================================
使い方
================================================

1. MODELERは起動していてもP0自体はruntime操作をしません。
   ただし解析を単純にするため、できれば閉じておいてください。

2. 00_RUN_REVIEWER_P0.bat をダブルクリックします。

3. PowerShellが以下を自動実行します。

   - 2つのSnapshotの存在確認
   - SHA-256 / サイズ記録
   - 7-ZipでZIP内容一覧
   - 必要なテキスト系成果だけ選択展開
   - rgがあれば限定キーワード検索
   - Pythonで既知事項と新規候補を分類
   - consumer候補 / bridge候補 / transform候補を順位付け
   - Ghidraで見るべきRVAだけ ghidra_targets.txt に出力

4. 完了すると REPORTS フォルダがExplorerで開きます。

================================================
ChatGPTへ送るもの
================================================

基本は以下だけで十分です。

  SUMMARY.md
  consumer_candidates.tsv
  novel_evidence.tsv
  ghidra_targets.txt
  evidence.json

必要になった場合だけ追加で:

  targeted_hits.tsv
  candidate_files.tsv
  manifest.tsv

巨大ZIP自体は再送不要です。

================================================
Ghidra targeted pass
================================================

P0で ghidra_targets.txt に新規候補RVAが出た場合だけ、
次段階でGhidra Headlessへ渡します。

P0では「候補選定」までを担当し、
過去の0x140f...静的corridorを無目的に再解析しません。

================================================
重要
================================================

このツールはSnapshot ZIPを変更しません。
元ZIPへ書込みません。
CSMCへ書込みません。
MODELER runtimeへhookしません。
semantic_promotion=false

今後の基本方針:
  ChatGPT = 何を見るか決める
  PowerShell = 司令塔
  7-Zip = archive
  rg = 限定テキスト検索
  Python = 証拠分類/重複排除
  Ghidra = 指定RVAだけ静的解析
  Frida/TTD/DynamoRIO = runtime側


================================================
P0.3 追加: ZIP不要のChatGPT受け渡し
================================================

P0.3から REPORTS に

  CHATGPT_PACKET.md

を自動作成します。

今後はFull SnapshotやREVIEWER_P0フォルダをZIP化して送る必要はありません。
基本的に、この CHATGPT_PACKET.md 1ファイルだけをChatGPTへ送ってください。

内容:
  SUMMARY.md
  ghidra_targets.txt
  consumer_candidates.tsv
  novel_evidence.tsv
  evidence.json

を1つのMarkdownへまとめたものです。

これによりChatGPT側のZIP展開エラーや巨大ファイルtimeoutを避けます。


================================================
P0.4 修正: scanned_text_files=0 対策
================================================

P0.3までのrunで、ZIP内容一覧とextract listは正常に作れた一方、
REPORTS/evidence.json が

  scanned_text_files = 0

になるケースを確認しました。

これは「新規証拠が0件」という意味ではありません。
Snapshot内には多数の .txt / .tsv / .json 等が存在しています。

P0.4では、約10〜12MBのSnapshot ZIPを一度すべて
EXTRACTED_TARGETED/<FULL|FOCUSED> へ展開し、
その後Python側で対象拡張子だけをbounded scanします。

研究範囲は広げません。
変更したのは7-Zipの受け渡し方法だけです。

成功時はコンソールに:

  Reviewer build: P0.4 (full extract, targeted scan fix)
  Extracted files: 1以上

と表示され、SUMMARY.mdの

  Scanned text files

が0より大きくなる必要があります。


================================================
P0.5 修正: Windows PowerShell 5.1 文字コード対策
================================================

P0.4で、01_RUN_REVIEWER_P0.ps1 内の日本語文字列が
Windows PowerShell 5.1 にUTF-8 BOMなしとして読み込まれ、
文字化けの結果、終端の " を正しく解釈できず ParserError になる
ケースを確認しました。

P0.5では、実行対象の .ps1 をASCII文字だけに変更しました。
日本語の説明は GUIDE_JA.txt 側へ残しています。

成功時:
  Reviewer build: P0.5 (ASCII PowerShell compatibility fix)

と表示されます。


================================================
P0.6 修正: NEW_RVA_CANDIDATES=0 の誤判定対策
================================================

P0.5は解析自体には成功しました。

  scanned_text_files = 438
  targeted_hit_count = 12046
  novel_evidence_count = 194

しかし new_rva_candidate_count = 0 でした。

原因:
旧analyzerは主に "0x140..." 形式だけをRVA候補として認識していました。
Full SnapshotのGhidra成果では、多くの関数が

  FUN_140xxxxxxxx

およびdecompileファイル名中の

  ..._140xxxxxxxx_FUN_140xxxxxxxx.c.txt

として記録されています。

一方 strings.tsv の 141e... のような裸hexはRTTI/データアドレスの場合があるため、
無差別にGhidra targetへ昇格させません。

P0.6では:
  ・FUN_... を実行コード候補として認識
  ・decompileファイル名のFUN_...も認識
  ・既知RVAは除外
  ・strings.tsv等の裸hexだけではcode targetにしない
  ・Ghidra targetはcode evidence >= 1を必須化

成功時:
  Reviewer build: P0.6 (code-aware RVA extraction fix)


================================================
P0.7 修正: P0.6の8954候補をcall graphノイズから分離
================================================

P0.6はFUN_アドレスを拾えるようになりましたが、
call_edges.tsvの広いcontext内に存在する多数のFUN_まで候補化したため、
8954候補・上位に共通helperが集中しました。

P0.7では:
  ・decompileファイルは「そのファイル自身の関数」だけ候補化
  ・string/xref/ranking系は「keyword直近140文字」のFUN_だけ候補化
  ・call_edges.tsv / functions.tsv / namespaces.tsv / strings.tsv /
    decompile index は候補の発生源にしない
  ・同一snapshot+file内の重複contextは最高点1件だけ集計
  ・既知の0x140d45d30 / 0x141657140を除外
  ・Ghidra target最大8件
  ・10_RUN_GHIDRA_TARGETSはP0.7 target list以外を拒否

重要:
  P0.6で生成されたghidra_targets.txtは実行しないでください。
  P0.7を一度実行し、そのCHATGPT_PACKET.mdを確認してからGhidraへ進みます。


================================================
P0.8 修正: 既存decompile重複排除 + indirect-dispatch
================================================

P0.7のcandidateは、Snapshot内ですでにdecompile済みでも
KNOWN_FACTSに無いだけでnew扱いになる場合がありました。

P0.8ではP0.7 classifierの後に
  03_P08_DECOMPILE_DEDUPE.py
を実行し、Snapshot内の既存decompile owner RVAをmanifest化します。

分類:
  ALREADY_DECOMPILED
    既存decompileあり。Ghidra再実行しない。
    EXISTING_DECOMPILE_REVIEW.md / .tsvで現在知識から再読。

  NEW_DIRECT_TARGET
    既存decompileなし。
    これだけghidra_targets.txtへ入る資格あり。

新規出力:
  decompile_manifest.tsv
  consumer_candidates_p08.tsv
  existing_decompile_review.tsv
  EXISTING_DECOMPILE_REVIEW.md
  SUMMARY_P08.md
  CHATGPT_PACKET_P08.md

10_RUN_GHIDRA_TARGETS.bat はP0.8 target listだけ受理します。

consumer本線の次レーンはgeneric string XREFではなく
既知loader vtableのindirect dispatchです。

  PW3DModelDataLoader     0x14195fad0  9 slots
  PWCanvas3DModelLoader  0x1417f6d30  9 slots

実行:
  20_RUN_VTABLE_DISPATCH.bat

詳細:
  VTABLE_DISPATCH_GUIDE_JA.txt

0x140a98310周辺のFBX skin/cluster風APIは別レーンです。
CSMC側call pathが接続されるまではsemantic_promotionしません。
