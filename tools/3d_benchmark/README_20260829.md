# ChatGPT 3D Multi-Building Plugin Benchmark
日付: 2026-08-29

## 結論
前回の一本道を3建物へ拡張し、外部Blender add-onの役割を分離してadapter試験した。
`Reference/Video → Recipe → Arch shell → Parametric repetition → Materials/UV → QA → Base44 realtime → GLB/OBJ → GitHub/Drive`

## 生成結果
- 東京の都市型コンビニ（架空）: v1→v3、最終19 objects / OBJ vertices 472 / GLB 14,328 bytes / PASS
- 東京の都市型ガソリンスタンド（架空）: v1→v3、最終24 objects / OBJ vertices 608 / GLB 17,284 bytes / PASS
- 東京の路面ラーメン屋（架空）: v1→v3、最終18 objects / OBJ vertices 472 / GLB 15,972 bytes / PASS
- 3件とも UVあり、参照texture欠損0、NaN/Infなし。
- texture front checkを追加し、コンビニ看板、GS canopy sign、ラーメン看板/暖簾を視覚確認。

## 良かった点
- pluginを機能別に分けると、単一巨大add-onへ依存せず交換可能になった。
- BlenderMCPは全工程の司令塔、Archimeshは骨格、Sverchokは反復、Asset Bridgeは素材、TexTools/HATは仕上げQAという分業が明確。
- Base44内で4種類のPresetを即時切替でき、PluginBenchmarkもLIVE表示可能。
- 3モデルを同じQA規格で比較できた。

## エラーと修正
1. Base44 video regression 1回目: `python` commandなし → `python3`へ切替。
2. その後 `imageio_ffmpeg` import不足 → dependency preflight/導入後に再実行、errors=0・12 screenshots生成。
3. to3D: URL検証は通るが3D jobが2回とも400。主系統から外し補助候補へ降格。

## 現実的な壁
- Base44 sandboxにBlender本体がないので、Archimesh/HAT/Sverchok/TexTools/BlenderGISのbpyネイティブ実行はできない。今回はrole adapterを実行。
- 真のviewport screenshot→AI判断→bpy修正の性能測定にはWindows Blender Relay/MCP接続が必要。
- Asset Bridgeの本物のPBR asset download/importはBlender実機とonline access設定が必要。
- GLBは交換用、OBJ+MTL+PNGをtexture debugging用の正本として保持する。
